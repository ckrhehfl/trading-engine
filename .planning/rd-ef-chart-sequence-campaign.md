## 현재 고정하는 순수 입력/회계 계약

신규 entry grid는 장 시작60~300분의15분 간격, 보유 갱신은 완료된5분 간격이다.
판단은 완료 시각2분 뒤라는 명시적 가정이다. 실제 주문/체결 시각은 별도 실행
계약에서 더 늦게 정한다. 최신60분 연속 OHLC가 없으면 chart unavailable이다.
각 분은 exact Fraction8채널이며, 거래량은 별도 값과 상태로 보존한다.
120분 범위의24개5분봉 슬롯은 장 시작 전과 결측을 구분한다. 전일 고저종가는
caller가 제공한 정확한 전 거래일의 전체 해당 구간이 확인돼야 사용한다.

peer proxy는 대상 종목을 제외하고 같은60분이 완전한 원래 peer5개 이상만
동일 집합으로 사용한다. 원래 분모와 제외 이유를 전부 남긴다. 사후 수익이 있는
행만 골라 공통 표본을 정의하지 않는다. 원본 금액·가격·수량은 부동소수점으로
손실시키지 않는다. 학습용 수치 변환의 precision/mask는 별도 고정해야 한다.

새 cash kernel은 전략별 immutable 장부다. 진입 때 기존 roundtrip 비용을
한 번만 낸다. 절반 매도는 남은 수량의 floor 절반으로 lot당 한 번만 가능하다.
배분된 원가·기납부 비용과 남은 원가를 exact arithmetic으로 대사한다. 미확인
매도가 발생하면 체결 안 됨으로 간주하지 않고 원래 재고·현금 보존 후 장부
변경을 정지한다. 이 kernel이 시간·위험 정책을 대신하지 않는다.

## 공식 기술 근거와 우리의 설계 선택

- [TCN 원 논문](https://arxiv.org/abs/1803.01271)은 일반 순차 문제에서 causal
  convolution을 검토한 근거다. 국내주식 비용 후 수익을 입증한 논문이 아니다.
- [PyTorch deterministic algorithms](https://docs.pytorch.org/docs/main/generated/torch.use_deterministic_algorithms.html)는
  지원 연산의 결정성 제어를 설명한다. 동일 runtime·입력·seed·단일 thread를
  별도 고정하며 다른 버전/장치의 동일 결과를 가정하지 않는다.
- [LightGBM 공식 parameter 설명](https://github.com/lightgbm-org/LightGBM/blob/main/docs/Parameters.rst)의
  deterministic/단일 thread 주의를 따른다. 실제 사용은 기존 pinned runtime와
  native parameter manifest를 재사용하고 latest 버전으로 바꾸지 않는다.

TCN 선택, 입력 기간과 peer proxy는 이번 프로젝트의 연구 제안이다. 공식 자료의
트레이딩 기법인 것처럼 표현하지 않는다. 아직 새 모델 수익 결과는 없다.

## 로컬 PyTorch 합성 학습 — 2026-11-05

기존 ED 보존 환경의 PyTorch 2.7.0+cpu를 재사용했다. 별도 소스 검토에서
worker 자원 제한이 자식 프로세스에 각각 적용될 수 있음을 발견했다. Linux
`RLIMIT_NPROC=0`을 worker에 적용하고, 제한이 면제되는 UID 및 권한을 거절했다.
worker가 한 task인지와 실제 적용된 hard limits를 실행 전후에 읽어 확인했다.
[Linux getrlimit 문서](https://man7.org/linux/man-pages/man2/getrlimit.2.html)

고정된 32×6×30 가상 입력과 361개 매개변수 모델로 세 번의 학습 갱신을 수행했다.
예측·gradient 유한성, 고정 합성 손실 감소, 미래 접미부 변경 시 과거 출력 불변,
숫자 상태 파일을 읽은 예측의 일치를 확인했다. 원래 영수증과 합성 모델은 로컬
private var에 보존했다. worker CPU 6.64초, controller CPU 약0.07초, 벽시계
7.37초, worker 최대 RSS 294636KiB였다. 실행 종료 때 worker 주소공간은
592957440바이트였으며 이는 최대 RSS와 다른 측정이다.

기존 자원 부족의 원인이었던 import를 통과했다. 이번 결과는 작은 가상 모델의
기술 증거다. 전체 규모 합성 자격과 실제 시장 자료 학습은 각각 0회다. 다음은
시간 분할·정답·모델·보유 정책을 고정하고 전체 자료 규모를 검증하는 단계다.

별도 연구 무결성 검토에서 보유 평가값의 결측이 가격이 확인된 매도까지
막는 불일치를 발견했다. 평가 공백은 과거 전체 평가와 신규 진입을 계속

## 실제 입력 이전에 고정한 모델 비교와 정답 — 2026-11-05

`configs/research/discovery/intraday-chart-sequence-comparison-v1.json`에 시간·
정답·모델·행동 규칙을 고정했다. 다음 거래일의 결과가 아니라 각 진입 뒤
15분·30분의 가상 시가 수익률을 계산한다. 보유 중 가능한 가격 고저점은 별도의
보조 정답이다. 중간 가격이 빠져도 시작과 끝이 확인된 수익률은 보존한다.
보관 분봉의 시가는 체결 가정이며 실계좌 기록이 아니다.

학습기는 1분봉60개와5분봉24개를 따로 읽고, 전일 수준과 거래량 가용 상태를
함께 입력받는다. 시장 추가 모델만 다른 대형주의 동시간대 움직임을 사용한다.
두 모델은 같은 과거 학습 시점과 공통 관측 표본으로 평가한다. 같은 TCN에서
이전 봉 순서를 섞어 재학습하는 대조군과, LightGBM 및 단순 기준선을 둔다.
정확한 최종 수치·갱신 규칙은 결과를 보며 바꾸지 않는다. 다섯 학습 방식과 두
시나리오의 다섯 시간 구간으로 실제 fit은 최대50개다. 이 단계는 수익 실험의
실행 자격이 아니다. LightGBM 입력 순서는 수치 변환 모듈의 38개 차트 항목과
시장 추가 모델의 4개 peer 항목으로 정했다. 실행기의 소스·환경·입력 binding은
별도로 검증한다.

보유 갱신은 최초 진입이 같은 두 경로를 비교한다. 30분 청산에 앞서 5·10·15분에
같은 모델의 15분 전망을 다시 계산한다. 첫 비양수 전망에서 보유를 한 차례
절반으로 줄이고, 연속 두 번 비양수면 남은 수량을 청산한다. 관측이 없는 갱신은
연속 판단을 끊는다. 일부 매도로 확보한 돈을 신규 매수에 쓰지 않는 비교로
청산 자체의 효과부터 분리하고, 별도 계좌 평가는 기존 자금 및 위험 기준을 따른다.

구현한 실제 비교 구조를 입력32개·출력6개·6 epoch의 가상 사례에서 실행했다.
worker CPU4.76초, 벽시계4.85초, 최대 RSS299264KiB였고 단일 task를 확인했다.
합성 입력에서 정해진 손실이 낮아졌고, 미래 접미부 변화와 숫자 상태 재생을
검증했다. 실행기와 영수증 원본은 로컬 private var에 보존했다. 보존된 Torch
환경에 NumPy가 없어 초기화 경고가 있었지만 이 입력은 native CPU Tensor로
완료했다. 실제 비교는 Torch와 LightGBM의 각 기존 고정 runtime에 맞춰 실행한다.
전체 자료 크기에서의 시간·자원 소모는 별도 합성 검증이 필요하다.

다음 단계 소스에는 정답과 각 라벨의 가용 시점, 차트/peer 수치 변환, 순서 제거,
TCN과 보유 갱신을 포함한다. 실제 공통 입력 묶음·시간 순 분리·모델 저장과
검산·계좌 실행 연결이 남아 있다. 지정 합성 테스트96개가 통과했다. 실제 자료를
열거나 수익을 계산한 횟수는0회다.

## 원본 입력과 독립 검산 연결 — 2026-11-05

`intraday-chart-sequence-input-v1.json`은 기존 CB·CC·CX 등록의 해시를
가리킨다. 연구 코드에서 새 수집을 시작하지 않으며, 보존된 원본과 기존 읽기
전용 인덱스의 지문을 검증한 뒤에만 입력을 사용한다. 새 EF 실행 계약은 기존
연구 실행의 별칭이 아니며 EF 전용 자원과 로컬 실행 경로에 묶인다.

원본 시나리오별 대상과 순위, 거래일, 소스 출처를 보존한다. 원래 종목과
날짜를 합친 단위에서 분봉을 한 번 읽어 두 시나리오의 동일 차트 입력을
생성한다. 현재 차트, 피어, 가상 체결 시가와 여섯 가지 정답을 원래 좌표별로
유지한다. 정답은 차트 입력과 다른 파일에 보관한다. 학습 분할은 평가 시작
전에 확인된 과거 정답만 읽고, 평가 행의 정답은 분할에 사용하지 않는다.

두 파일의 바이트 지문과 등록을 연결한다. 검산기는 저장값을 기준으로 정답을
재현하는 대신, 기존과 독립된 분봉 해석기로 원본을 다시 해석하고 차트·피어·
가상 시가·정답·시간·결측을 별도로 계산해 저장된 모든 좌표와 비교한다.
작은 가상 원본으로 전체 경로를 통과했고, 임의로 바꾼 차트 값은 검산에서
거절됐다. 로컬 세 역할의 별도 가상 수명주기와 기존 실행 가드 회귀 검사도
통과했다. 전체 크기의 가상 개발 진단은 별도 실행하며, 병합 후 정식 자격이나
실제 성과 실험으로 계산하지 않는다.

TCN과 LightGBM은 동일한 원본 좌표에서 공통 입력을 얻는다. TCN의 차트 단독
입력은 시장 채널에 상수만 넣고, 시장 추가 입력은 그 자리에 관측된 피어를
넣는다. LightGBM 가상 자료 학습, 모델 저장 후 예측과 독립 트리 계산이
통과했다. PyTorch는 CPU 버퍼를 사용하도록 연결했고, 저장한 계수를 직접
재생하는 검산 경로를 구현했다. [PyTorch 2.7 버퍼 API](https://docs.pytorch.org/docs/2.7/generated/torch.frombuffer.html)

실제 시장 학습 전에는 원래 수명주기와 전체 크기의 가상 검증 영수증, 정상
릴리스, 원본 입력 해시 및 새 저장 파일의 독립 검산이 필요하다. 이어서 실제
시간 분할의 다섯 학습 모델과 대조군을 동일 기준에서 실행하고, 고정 청산과
부분 축소·청산의 장부와 비용을 검산한다.
