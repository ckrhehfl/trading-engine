## 단계별 실행과 재사용

1. **입력 적합성:** 고정 EB 결과의 날짜/종목/신호/시각/원천 상태만 좁게
   투영할 수 있는지 소스에서 확인한다. 실제 결과 파일을 열면 내부 라벨도
   파싱되므로 새 실제 입력 접근으로 등록/로그한다. 가격 수익을 재계산하지
   않았다는 것과 원문을 읽지 않았다는 것을 혼동하지 않는다.
2. **필요 원자료:** 기존 DB의 발견용 기간 내 시장 대표 가격·주식 거래량과
   시간 공백을 read-only로 감사하는 정확한 쿼리 계약을 만든다. 스키마/목록
   확인과 가격·수익 계산을 구분하고, 전진/예약 자료를 범위에 포함하지 않는다.
3. **공동 계좌:** 기존 신호와 OPEN 체결 경계를 재사용하고 최소 정수주/현금
   장부를 연결한다. EB 결과에는 완전한 분별 보유 평가가 없으므로 단건 평균을
   합쳐 계좌 성과로 보고하지 않는다.
4. **정보 조합:** P04–P07은 같은 특징 관측 가능 범위의 대조와 비교한다.
   선택/명시적 탈락/미확인/진입 무효/결과 미확인을 따로 보존한다.
5. **라우터·학습:** P03를 기준으로 P08–P10의 추가 가치를 평가한다. 누적
   노출·회전·비용·날짜 의존성까지 고려하며 과거 개발 구간의 재평가임을 밝힌다.
6. **남은 계열:** P11/P12는 예전 정의와 실패/미실행 이력을 보존하여 새 단위를
   등록한다. 기술 실패를 전략 음수로 기록하거나 자동 재시도하지 않는다.
7. **모의 준비:** existing simulator/mock/no-order 연결의 재사용과 현물 경계를
   확인한다. 실제 forward 관측·paper 주문·live 활성화 또는 KIS kill switch
   변경은 포함하지 않는다. 가동 준비와 전략 수익성 인증을 분리한다.

공통 입력/장부/비교 구조를 재사용해 원자료 탐지와 무거운 인코딩을 불필요하게
반복하지 않는다. 계산 단위마다 producer-independent 검산 경계와 소스 해시를
고정한다. 변경된 소스는 별도 source/integrity review와 필수 CI/정상 머지를
거친다. 리뷰 요청만으로 통과라고 하지 않으며 필수 검사를 우회하지 않는다.

checkout만 정상 머지 소스로 반영한다. `.env`/DB/연구 로그를 새 작업 트리에
복사하지 않는다. 보호 미추적 원본 둘은 reads/imports/tests/scans/staging 밖에 둔다.
새 자료 획득·holdout/forward·비용 지출·위험/매매 범위 변경·승격은 별도 판단이다.

## 2026-10-29 — 첫 입력 적합성 단위의 사전등록

등록 파일은 `configs/research/discovery/intraday-campaign-readiness-v1.json`이다.
이는 12개 성과 정책보다 앞선 입력 감사이며 새 평균 수익률/가격 라벨/학습은
계산하지 않는다. 두 EB full report는 기존 독립 검산 완료 SHA로 고정한다.
보고서 전체 JSON을 파싱하므로 가격/라벨 값도 메모리에 들어간다는 사실을
명시했다. 출력은 기존 target/신호/조건 상태, 특징 관측 여부, 원천 연결과
진입/청산 시각의 metadata로 제한한다. 이 좁은 출력만으로 원문을 안 읽었다고
주장하지 않는다. A/B 동시 시각·동일 종목·알려진 보유 구간 겹침은 시간 진단이며
공동 운용의 자금 제약이나 실현 계좌 수익률이 아니다.

기존 운영 DB의 원래 발견 기간 내 `KRX:*`와 `KRX-INDEX:*` 1분행만 조사한다.
정확한 DB 경로는 등록에 고정했다. 가격 열은 SQLite authorizer에서 거절하며,
거래량·거래대금은 NULL/빈 문자열/값 존재만 분류한다. 실제0과 미확인을 합치지
않고, 값 존재를 유효한 숫자/가용한 과거 자료의 증거로 쓰지 않는다. 인덱스
namespace에 행이 없다는 결과도 시장 정보가 경제적으로 존재하지 않았다는
판단이 아니다. 종목 선정·대리변수 정의·성과는 이 단계에서 바꾸지 않는다.

SQL 집계와 다른 timestamp/presence 스트림의 독립 재구성을 동일 read-only
transaction에서 대조한다. 운영 수집기가 계속 쓰는 DB이므로 파일 전체 해시나
실행 전후 mtime 일치를 요구하지 않고 읽은 snapshot의 metadata를 해시한다.
필수 열 부재·무결성 오류·예산 초과는 실패이며 실제0/완료로 바꾸지 않는다.
조회 예산60초/200M VM steps는 두 통과가 공유한다.

실행기는 새 private source `var/ec-readiness-execution.py`, 독립 report 검산은
`var/ec-readiness-independent.py`, 합성 보고서는 `var/ec-readiness-fixtures.py`로
구분한다. 세 원본과 재귀 project-import closure를 정확히 해시한다. 등록된 두
257일×20종목×D+1/D+2 보고서와 2,000,000행 합성 DB를 실제 GCP Python runtime에서
동일 producer/검산 경로로 먼저 검증한다. CPU300/AS512MiB/wall1200/nice10 및
serial/무자동재시도를 그대로 적용한다. 합성 입력 생성·저장·조회·검산·직렬화도
한 실행 예산에 포함한다. 이 단위는 가격/학습 12개 정책의 예산을 대신하지 않는다.

실제 실행 전 최종 소스 별도 리뷰와 연구 무결성 리뷰, 네 필수 CI, 정상 머지를
완료한다. 격리 연구 checkout만 머지 소스로 반영하고 수집기 HEAD/dirty 상태가
변하지 않았는지 확인한다. canonical started를 실제 보고서/DB 접근보다 먼저
기록하고 전용 잠금·exclusive output·출력 재해시·canonical span을 보존한다.
이 문단은 실행 계획이며 합성/실제 검증 완료 증거가 아니다.

### 합성 v1 중단 기록 — 실제 자료 접근 0회 유지

새 metadata 테스트23개, 새/기존 inventory 및 planning 인덱스 지정 테스트는
91 passed/1 skipped였다. private 독립 검산은 실제 EB builder의 소형 합성 결과,
시각 변경·행 순서·8종 변조 거절을 확인했다. 이것은 전체 규모 검증을 대신하지
않는다. 예비 실행기 리뷰에서 canonical logger의 window schema 불일치를 발견해
실행 전에 수정했고, 실제 실행 시 GCP 원본의 합성 publication/output/canonical

### P01–P03 인과적 계좌 비교 명세 초안

`configs/research/discovery/intraday-campaign-account-v1.json`에 다음 단위의

현금 장부는 정수 수량·정확한 금액·비용 1회 반영·교차 차입 금지를 담당한다.
분 단위 계좌는 이전에 예약한 청산, 새로 가용한 보유 분의 가격, 위험 평가,

진입 가격을 초기 평가 기준으로 삼고, 이후 반드시 필요한 분이 없으면 계좌를
계속 미확정으로 남긴다. 미확정 이후의 후속 현금·청산은 조건부 계산이며,
확정된 손익 집중도에 섞지 않는다. 다른 소스에서 이미 확인된 같은 규칙을
현재 실행이 인증했다는 식으로 표현하지 않는다.

연속 계좌와 매일 같은 자금으로 시작하는 별도의 하루 진단을 구분한다.
하루 진단에 미확정된 이전 주·월의 손익을 만들어 넣지 않는다. 원래 모든
대상·날짜·0기회 주를 유지하며 세 정책 모두 계좌 경로가 식별된 공통 날짜의
조건부 비교를 따로 낸다. 이는 전체 원래 종목군이나 실제 증권 계좌의 재현이 아니다.

자체 표본 진단은 계좌 손익/초기자본 단위로 계산한다. 주식 한 건의 가격
비용 bp를 계좌 하루 손익 bp에 그대로 대입하지 않는다. 같은 날짜의 배정금에
실제로 부과한 가정 비용을 기준 크기로 삼고, 기존 날짜 의존성 보정 방식을
재사용한다. 비교는 탐색이며 표본 진단 통과나 전략 합격을 선언하지 않는다.
기본 단위의 생산·독립 검산·저장은 하나의 기존 기본 자원 예산을 공유한다.

별도 리뷰·CI·머지를 대신하지 않는다. 독립 계좌 재구성과 실행기를 연결한 뒤

않는다. 기존 실패는 보존하고 같은 승인 상한으로 새 전체 자격을 확인한다.

운영자는2026-10-30에1번인 로컬 WSL 전환을 명시적으로 선택하고, 같은 자원
한도와 독립 검산 기준으로 실제 A 단독·B 단독·공동 운용 비교부터 이어가도록
지시했다. PR378은 최종 별도 소스·연구 무결성 리뷰와 push/PR 필수 CI를 거쳐
정상 머지됐고 격리 GCP 연구 체크아웃에 소스가 반영됐다. 수집기 경로와
프로세스는 변경하지 않았다. 이 소스 준비는 실제 계좌 비교 완료가 아니다.

v1/v2와 모든 실패를 보존한 채 v3 실행 명세를 추가한다. 과학적 계약은
그대로 두고 계산 host와 동일 host 전체 경로 자격만 개정한다. 앞선 로컬
전체 합성 완료는 새 전송·기록 연결부를 포함하지 않았으므로 새 자격으로
그대로 채택하지 않는다. 상세 실행 메타데이터는 운영자용 비공개 기록에 둔다.

단일 공유 자원 상한은 유지하고, 역할별 hard limit 합이 그 상한을 넘지
않도록 분할한다. 기존 원본 보고서 두 개와 가격 압축 파일만 원래 pin에
결속해 worktree 밖 전용 WSL native cache로 전달한다. 데이터베이스·키·기존
연구 로그는 전달하지 않는다. GCP canonical started 뒤에만 입력을 열고,
같은 원래 후보의 생산·독립 재구성·저장/재해시·GCP 결과 저장까지 완료한 뒤
completed를 남긴다. 부분 실패와 미종결 marker는 보존하고 자동 재시도하지 않는다.

현재 단계는 연결부 구현과 합성 검증이다. 실제 계좌 성과와 전체 캠페인
완료를 주장하지 않는다. 최종 소스와 private manifest, runtime, 역할별
한도 및 동일 전체 경로 자격을 결속하고 별도 리뷰·CI·정상 머지 후 실행한다.

### WSL 연결부 합성 검증과 발견 사항 수정

기존 계좌 생산·독립 검산을 재사용하는 stdio 연결부와 private 실행기를
구현했다. 자식 생성 시점의 주소 공간까지 포함하도록 역할과 Git 보조 작업의
hard limit을 분할한다. 기존 logger의 별도 Git 조회도 같은 보조 작업 예산에서
실제로 조회하도록 연결했다. 값이나 코드 버전을 임의로 만들어 넣지 않는다.

별도 조기 소스 검토에서 파이프 선행 버퍼링에 의한 대기 멈춤과 출력 경로를
바꿔 중단 표시를 피할 수 있는 경로를 발견했다. raw pipe 처리와 고정 실제
출력/전역 중단 표시로 수정했다. 원격 canonical 완료 뒤에도 소비자의 완료
영수증 저장 확인 전에는 표시를 지우지 않는다. 확인 프레임 손실은 기존 원격
기록을 그대로 보존하고 로컬 성공으로 처리하지 않는다.

작은 전체 연결 검증은 정상 완료·완료 응답 손실·소비자 확인 손실·원격 결과
저장 실패를 재현했다. 초기 자원 검사에서 AST 전체 재파싱이 제한된 부모의
메모리를 다시 요구하는 경로도 발견해, 최초 인증한 이름 집합을 유지한 파일별
streaming 재해시로 바꿨다. import/config 변경은 원래 파일 pin 불일치로 계속
거절한다. source-only launcher는 같은 PID로 controller를 exec해 별도 미계측
Python 실행 예산을 추가하지 않는다.

최종 지정 명세·transport·private 연결·launcher·문서 검사는140 passed,
1 existing skip이었다. GCP·실제 입력을 사용한 결과가 아니며 전체 규모의
동일 WSL↔GCP 자격과 실제 계좌 결과는 아직 없다. 최종 별도 리뷰·필수 CI와
정상 머지 뒤 새 전체 경로를 검증한다.

### 서로 다른 host의 원본 경로 검사 수정

전송 명세의 `original_path`는 발신 host의 원본 위치를 나타내는 메타데이터다.
이를 수신 host의 파일시스템에서 `lstat`하던 오류를 수정한다. 사용자 홈의
이름과 접근 권한이 다른 환경에서는 정상적인 전송 명세도 거절될 수 있었다.
원본 경로는 절대 POSIX 문자열인지, NUL이나 상위 경로 이동이 없는지만
검사한다. 실제 파일을 읽거나 쓰는 host에서는 기존 파일·부모 경로의
symlink 거절, 단일 hardlink, 크기, 해시와 변경 감지를 그대로 적용한다.

두 host가 같은 사용자 경로를 공유하지 않아도 검증할 수 있는 회귀검사와
실제 I/O의 기존 보호 검사 유지 여부를 추가 확인한다. 과학적 계약과 자원
상한은 바꾸지 않는다. 이 수정도 최종 별도 리뷰·필수 CI·정상 머지를 거쳐
반영하며, 이전 실패를 보존하고 새 전체 경로 자격을 확인한다.

수정 전 회귀검사에서 기존 `PermissionError`를 재현했다. 수정 후 공개
transport와 지정 소형 연결 검사는47 passed였고, 문서 검사는84 passed,
1 existing skip이었다. 실제 파일의 source/destination/부모 symlink 및
source hardlink 거절과 정상 전송·시작 전 단절·완료 확인 유실을 확인했다.
이 검사는 실제 시장자료 비교 완료나 새 전체 규모 자격을 뜻하지 않는다.

### 고정 규제 모델과 LightGBM의 과거 전용 선별 연결

원래 H4/H5 소스는 PR383의 정상 머지로 완료했다. 실제 실행 원본과 감사 상태는

두며, 각 learner가 독립된 전체 실행 단위라는 점은 유지한다.

기존 원본 보고서가 살아 있을 때 signed Fraction 숫자와 원래 가격 라벨을
별도 투영한 뒤 전체 보고서를 해제한다. 생산의 원래 EA 산술과 별도 원시 산술을

확인한다. 계좌의 정수 수량 손익으로 지도학습 정답을 바꾸지 않는다. 같은 날짜
원시 종목의 반복 라벨 파싱은 당일 한정 batch 검산으로 재사용한다.

같은 원본 가격 압축 파일을 두 번 완전히 인증한다. 첫 순회는 인과 특징과
라벨의 고정 sidecar, 두 번째는 동결한 예측으로 평가 날짜의 계좌를 계산한다.

두 순회 모두 확인하되 최초 학습 전용 날짜는 계좌와 기회 빈도 분모에 넣지 않는다.
평가 주의 원래 날짜와 0기회 주, 경계 주의 불완전성도 유지한다.

학습 표본은 특징 관측과 원래 알려진 라벨, test opening 이전 성숙 조건을
모두 만족해야 한다. 모델이 없는 fold를 빈 현금 전략으로 표시하지 않고 그
fold의 선택 계좌 날짜를 시초부터 불명확하게 한다. 연속 계좌의 불명확함은
나중 fold가 학습 가능해져도 복구하지 않는다. 원래 분봉 결측과 다른 원인으로
따로 보고하며 대조군에 미래 라벨을 요구하지 않는다.

수치 어댑터는 학습 전용 변환을 쓰는 고정 ridge와 native LightGBM이다.
전체 native 기본값과 매개변수, finite float 직렬화, 행 순서/라벨/행렬/실행환경
해시를 고정한다. ridge는 별도 변환·정규방정식 잔차와 scalar 예측을 확인한다.
LightGBM은 입력 라벨과 native 저장 정밀도를 각각 기록하고 저장 Booster를
재로드하여 예측을 대조한다. 학습 내부까지 별도 구현했다는 주장은 하지 않는다.

준비했다. 다른 checkout의 venv를 복사하지 않았고 기존 source/실행 영수증은
보존했다. 제한된 import-only 진단은 메모리 상한 안에서 통과했지만 학습이나
전체 경로 자격의 증거가 아니다. 개발/CI 환경에도 같은 버전을 명시하고 lock을
갱신한다. lean coordinator/controller는 numerical import를 하지 않는다.

실제 라벨 준비율·학습·새 성과 완료를 뜻하지 않는다. 최종 source/private/
numerical/runtime 결속, 별도 최종 소스·연구 무결성 리뷰, 필수 CI, 정상 머지와
