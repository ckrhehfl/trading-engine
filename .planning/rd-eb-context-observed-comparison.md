## 연결부의 사실·가정·미확인 구분

CB의 원 observation_date/available_at/selected_at와 서비스별 retrieved_at 및
data_vintage 매핑을 sidecar로 보존한다. EA 단일 clock/type용 변환은 원 값을
증명한 것처럼 표현하지 않는다. 날짜 관측 종료는 해당 기준일 KST 자정 다음 시각
직전으로 표시하는 표현 규약이며 별도의 과거 공개시각 증거가 아니다. 수집 시각은
원 매핑의 최신 시각, vintage는 원 매핑의 canonical hash로 묶고 원 매핑도 남긴다.

가격의 동일 종목 내 단위와 수량 기준선은 기존 공급자 저장 단위에 의존하는
탐색 가정이다. 기업행사 전후의 경제적 비교 가능성/과거 수정 이력은 미확인으로
보고한다. 문자열 basis 일치가 실제 단위 인증을 뜻하지 않는다. CC/CX의 원시
timestamp별 fetched_at 연결을 검사하고 mismatch는 자료 무결성 실패로 둔다.
현재 동일 bucket 또는 fetched_at 집합만으로 같은 vintage를 주장하지 않는다.

동료는 target을 제외한 원래 고정 대상 전원이다. 5명 quorum이나 관측 종목만
평균내는 방식으로 바꾸지 않는다. PriceWindow는 필요한 전 분을 확인한 후 첫
OPEN/마지막 CLOSE를 사용한다. 미확인 동료는 전체 문맥 unknown으로 유지한다.
분봉 end+2분 가용 시각, 모델링 달력, 체결 지연·시가 체결·비용은 가정이다.

## 사전 고정 비교와 종료 조건

셋업당 한 실행 단위로 D+1/D+2를 함께 처리한다. 순서는 A 뒤 B이며 결과가 나빠도
다른 기준으로 교체하지 않는다. B는 A의 성공/양의 결과에 의존하지 않는다.
두 정책을 독립 표본으로 합산하지 않는다. 기존 EA의 모든 수치는 그대로다.

1. 원래 모든 target의 가격 신호/알 수 없음/신호 없음과 문맥 선택/탈락/unknown,
   진입 무효, 가격 결과 unknown을 보존한다. 주별 0회와 전체 reference 분모 유지.
2. 각 셋업의 모든 필수 문맥을 관측한 SAME 후보에서 basic과 조건부 팔을 비교한다.
   A는 basic/volume_only/market_relative_only/both, B는 basic/market_context.
   별도 basic_all은 전체 가격 후보 진단이며 공통 비교군과 혼동하지 않는다.
3. 모든 보고 팔의 현재 own-label dispersion/MDE를 평균 보고 전에 계산한다.
   기존 날짜 군집·5세션 블록, 2,000회 seed0, 최대 SE 규칙을 재사용한다.
   빈 표본/0분산은 uninformative, 33bp보다 큰 MDE는 underpowered로 남긴다.
   이번 사용자 승인은 이 상태의 제한 탐색 보고까지 허용하며 통과로 바꾸지 않는다.
4. exact gross/net33/net43 평균, 양/비용초과 비율, 팔별 기술적 95% 구간,
   corrected/naive SE 비율을 보고한다. 같은 관측 범위의 선택 평균−basic 평균은
   기술적 차이로만 보고한다. 겹치는 두 집단에 독립 표본 SE/p-value를 붙이지 않는다.
5. 고정 달력 전후반과 모든 종목의 건수·기여도를 보고한다. 결과를 본 후 좋은
   구간/종목만 고르지 않는다. A/B 중복 기회를 별도 표시하며 계좌 빈도/수익률로
   단순 합산하지 않는다. 주 15회는 기회 목표이지 강제 매수나 합격 조건이 아니다.
6. 두 결과와 한계를 보고하면 이번 round 종료. 수익 후보 찾을 때까지 튜닝하지
   않는다. 방향 폐쇄·전략 합격·실거래·예약 자료 접근은 이번 결과로 허용되지 않는다.

## 구현·실행·검증 순서

기존 순수 준비 함수와 가격 label 산술을 재사용하고 실제 탐색 호출과 합성 호출을
정직하게 구분한다. 실제 입력에 synthetic=True를 붙이지 않는다. 새 streaming
producer와 독립 raw reconstruction을 만든다. 원시 자료는 하루분 가격과 필요한
과거 거래량 창만 유지하며 반복 메타데이터와 인코딩을 줄인다.

각 셋업은 producer, 독립 재구성, 핀 재확인, substantive 결과 인코딩까지 ONE
process/CPU300초/AS512MiB/wall1200초/nice10 안에서 끝낸다. 실제 실패 후 예산을
재설정하거나 결과 일부를 채택하지 않는다. 동일 전체 규모 invented profile을
실제 실행 환경에서 먼저 통과시키며, source/runtime/input/output binding, separate
source/integrity review, 필수 CI와 정상 동일 tree 병합 후 실제 읽기를 시작한다.
시작 로그가 입력 읽기보다 앞서고 완료 로그는 예산/검산 완료 뒤다. 원본·실패와
부분 출력은 보존한다. 자동 actual retry는 없다.

현재 실제 비교 0/2. 완료 조건은 두 셋업 실제 결과(또는 인증된 실제 자료 한계),
독립 검산, 리뷰·CI·정상 병합, 한국어 결과/다음 단계 보고다. 코드만 끝나거나
등록만 했다는 이유로 Goal을 완료 처리하지 않는다.

## 2026-10-27 — 연결부 합성 구현과 실제 실행 전 검증

원래 CC/CX 행 메타데이터를 보고서에 중복 복사하지 않는다. 원본 archive 핀,
청크 canonical hash, 순서 있는 timestamp/fetched_at 행 연결 hash와 행 수를
보존하고 원래 고정 archive 청크를 메타데이터 위치로 명시한다. 비교는 실제
원시 timestamp/fetched_at의 multiset을 사용해 중복 개수까지 맞아야 한다.
이 방식은 원본 정보를 삭제하거나 단순 집합 일치를 같은 vintage로 오해하지 않는다.

별도 생산 구현/합성 라벨/독립 검산/실행 경계/문서 색인 통합 검증은 218 passed
(70.10s). 이후 동일 거래일 peer/start/end의 완성 창 캐시로 중복 계산을 줄였고
생산자 지정 테스트 28개가 통과했다. 아직 실제 입력은 읽지 않았다.

A/B 중복은 B의 같은 실행 예산 안에서 고정 선행 A의 완료 publication만 읽어
계산한다. A 경로는 고정하고 실제 A 완료 후 그 원문 hash를 B 실행 등록에 묶는다.
같은 종목/일자의 선택, 둘 다 가격 결과 known인 선택, known 보유 구간의 엄격한
교집합을 각각 별도 독립 계산과 대조한다. 경계 시각만 같은 경우는 중복 보유가
아니다. A/B 수익 통계는 다시 계산하지 않으며 계좌 매매 횟수/수익률로 합산하지 않는다.

## 2026-10-28 — 실행 전 합성 실패와 독립 실행 경계 수정

EA-A의 전체 규모 GCP invented v1은 생산 계산 중 CPU 300초 한도를 초과했다.
실제 EB 입력은 읽지 않았으며 해당 합성 실패와 부분 증거는 보존한다. 자원 한도,
명세와 검산 범위를 그대로 유지하고 반복 계산만 줄인 뒤 새 버전의 전체 규모
합성 자격 검증을 수행한다. 합성 실패는 전략의 성과 결과가 아니다.

별도 소스 검토에서 A가 실패하면 B까지 완료 publication을 요구하여 막히는
문제를 발견했다. 앞의 완료 publication 경로는 A가 완료된 경우에 적용한다.
A가 실패한 경우에는 같은 소스·명세·실행 등록·원본 핀과 canonical
started→failed 쌍을 묶은 단말 실패 증거를 B의 원자료 접근 전에 검증한다.
이때 B 자체 비교는 독립적으로 진행하고 A/B 중복은 unavailable로 남긴다.
A의 부분 성과를 채택하지 않는다. 파일 부재, 빈 stdout 또는 started만 남은
상태는 단말 실패 증거가 아니며 자동 재실행을 허용하지 않는다.

생산자의 과거 거래량 창 검증은 실행별 최대 512개의 강한 참조 캐시를 사용한다.
원래 검증을 통과한 불변 창만 저장하며 더 이른 판단 시각·다른 식별자·다른 창은
재검증한다. 가변 타입은 기존 검증 경로를 유지한다. 전체 보고서의 캐시 유무
동등성과 시각/단위/결측 경계를 포함한 준비·생산자 테스트 128개가 통과했다.
A 실패 연결부 합성 경계는 33개가 통과했다. 이 테스트는 전체 규모 실행 자격이나
실제 성과를 대신하지 않는다. 새 source/runtime 전체 규모 검증은 아직 남아 있다.

전체 규모 GCP invented v2는 생산 보고서를 저장한 뒤 독립 검산 중 CPU 한도를
초과했다. 시작 2026-10-28 09:30:52 UTC, 보고서 저장 09:34:55 UTC, 실패
09:35:52 UTC이며 보고된 CPU는 300.012초다. v2 부분 보고서는 탐색 결과로
채택하지 않는다. 로컬의 같은 전체 규모 합성 진단은 cProfile을 포함하여 생산
60.601초, 인코딩 0.450초, 독립 검산 34.207초였지만 GCP 자격을 대신하지 않는다.

원인을 추측하여 자원 한도를 높이지 않고 기존 v2 합성 자료에 한정한 GCP CPU
진단을 수행했다. CPU 180초에서 진단을 종료하고 호출 비용만 보존했다. 당시
1,398개 가격/거래량 청크를 처리했으며 분봉 집계 46.065초, 보유 분 가격 검증
21.897초가 주요 누적 비용이었다. 원자료 시장 경로·API·DB 접근은 없었다.
이 근거에 따라 분봉 집계와 가격 비교의 불필요한 변환을 줄이되 동일 원시 행의
식별자·시각·가격 유효성·중복·결측·OPEN 전용 경계를 유지한다. 실제 EB 비교는
여전히 0/2이며 새 전체 규모 검증과 최종 소스 리뷰/CI가 필요하다.

가격 검증은 유한한 양의 순수 Decimal의 정확한 크기 비교를 유지하고, 손절에
필요한 종가만 Fraction으로 변환한다. Decimal 하위 클래스는 이전 경로를 유지한다.
준비/가격 라벨 181개 테스트가 통과했다. 분봉 집계는 정상 정렬 시각의 정수 분
버킷과 검증된 순수 문자열 가격의 세션별 한정 캐시를 사용한다. 범위 밖 시각,
비정렬 개장, 중복/결측/잘못된 가격은 이전 결과와 대조한다. 새 전체 규모 합성
